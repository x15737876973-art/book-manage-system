# 面试预演：这 5 个问题你必须答得出来

<!-- 简历写什么，面试官就问什么。以下是对应你简历每个点的必答题。 -->

### 1. "你说做了 48 个类的系统，具体怎么分层的？"

**答**：Controller（Servlet）→ Service/DAO（数据访问）→ Entity（实体），配合 Filter 做编码与权限拦截。

### 2. "HikariCP 连接池解决了什么问题？"

**答**：每次 `DriverManager.getConnection()` 都要 TCP 握手 + MySQL 认证，约 5-20ms。连接池预建物理连接并复用，把获取连接降到微秒级，同时限制最大连接数防止打爆数据库。我配置了最大 10 连接、最小空闲 2、最大存活 30 分钟。

### 3. "你说的库存防超卖怎么实现的？"

**答**：`UPDATE books SET available_stock = available_stock - 1 WHERE id = ? AND available_stock > 0`。这条 SQL 依赖数据库行锁保证原子性，如果库存为 0，UPDATE 影响 0 行，业务层判断受影响行数为 0 就返回"库存不足"，不会扣成负数。

### 4. "事务一致性问题你遇到过什么坑？"

**答**：最初每个 DAO 方法各自 `getConnection()`，看似在 `inTransaction` 里，实际各方法用的是不同连接，回滚只能撤销最后一条语句。后来用 `ThreadLocal` 把事务连接绑定到当前线程，DAO 内部通过 `acquireConnection()` 优先取线程绑定的连接，才真正做到跨多个 DAO 的原子性。

### 5. "81 个测试怎么保证有效？"

**答**：用 H2 内存数据库（`MODE=MySQL`），每个测试方法前重置数据，测试互相独立。重点测边界：分页页码为 0/负数、库存为 0 时扣减、SQL 注入 payload、事务异常回滚。写测试时还发现了一个真实 bug：寒暄词"谢谢"被当成检索关键词。
